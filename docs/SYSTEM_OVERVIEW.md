# PARKPULSE — Complete System Overview

ParkPulse is a parking management system with role-based access (Admin, Staff, Member), real-time slot management, reservations, ticketing/billing, membership plans, reporting, and an AI assistant.

**Stack**: Spring Boot 3.2.2 (Java 17) + Spring Security (JWT) + Spring Data JPA, H2 file DB (MySQL profile available), React 18 + Vite 6 + Tailwind v4 + recharts. Backend port `8080`; H2 console at `/h2-console`; frontend dev on `5173`.

---

## 1. Authentication & Access Control

### Login flow (`POST /api/auth/login`)
Tries three credential stores in order:
1. **Admin** — from `users` table (`admin`/`admin123`, BCrypt). Returns role `ADMIN`, access `admin`, permissions `["*"]`.
2. **Staff** — from `staff` table; deactivated staff → 401 "Your account has been deactivated." Token role = `access.toUpperCase()` (ADMIN/MANAGER/OPERATOR/VIEWER/CUSTOM); permissions = staff's `customPermissions`.
3. **Member** — from `members` table; suspended/inactive → 401. Returns full member profile: `name, email, plan, status, joinedDate, vehicles, vehicleList, qrCode, billingCycle, nextRenewalDate, daysRemaining`. QR is **lazily generated and persisted** if missing. Fixed permissions: `["parking-slots","settings-profile","settings-password"]`.

### Roles & Permission model
- **Access levels**: `admin | manager | operator | viewer | custom` (staff) + `member` + `ADMIN` (super).
- **Frontend `levelDefaults`**: admin=`['*']`, manager=dashboard/analytics/reports/tickets/parking-slots/staff/member mgmt + all settings, operator=dashboard/parking-slots/tickets, viewer=dashboard, member=parking-slots/settings-profile/settings-password.
- **Backend `@PreAuthorize`**: tickets write/delete/checkout need `tickets|*`; parking slot read needs `parking-slots|member|*`; checkout needs `parking-slots|tickets|*`; reservations/chat = `isAuthenticated()`.
- **JWT**: HS256, 24h expiry, carries `role/userId/access/permissions`; filter converts permissions to authorities.
- **Access-control settings** (editable): default permissions per role, custom roles JSON, max concurrent sessions, MFA flags for admin/manager, session timeout, lockout rules.
- **Password services**: verify/change password for Admin, Staff, and Member via `/api/auth/verify-password`, `/api/auth/change-password`, `/api/staff/verify-password`, `/api/staff/update-password`.

## 2. Member Features

### Self-registration (public `RequestAccessModal`, 6 steps)
Personal → Vehicle (plates) → Confirm → Plan selection → **Checkout** (card validation via `/api/payments/validate-card`, username availability via `/api/payments/check-username`, auto-generated username/password) → Welcome (shows QR + temp credentials).

### My Subscription view (member home)
- Profile header (name/email), **QR code** (`data:image/png;base64` generated by ZXing encoding `{"id","name"}`).
- Plan, status badge, billing cycle, joined date.
- Renewal: next-renewal date + **days-remaining countdown bar** (computed server-side by `calculateSubscription` iterating months/years from joinedDate).
- **Registered vehicles list** (plates with type/make/color), "Reserve a Slot" CTA.

### Member Parking flow
- Slot map shows Available + Taken + Reserved; members cannot park directly — they **reserve** using a picker of their registered vehicles → `POST /api/reservations` (sets slot reserved).
- Members can cancel their own reservation; see others' reservations as "Reserved" only.
- Members are **excluded from Analytics and Vehicles** sub-views (sidebar hidden + defensive render guard).

## 3. Parking Slots (`/api/parking`)

### Slot model & operations
- `ParkingSlot`: id (e.g. `A1`), occupied/reserved/maintenance flags, vehicle/vehicleType/ownerName/phone/notes/entryTime.
- **Toggle/occupy**: `POST /parking/slots/toggle/{id}` — validates vehicle type against zone, auto-creates an **ONGOING ticket**, records session.
- **Reserve/release**: `POST /parking/slots/{id}/reserve`, `/release-reservation`.
- **Maintenance**: `POST .../{id}/maintenance`, `/clear-maintenance`.
- **Checkout**: `POST /parking/slots/checkout/{id}` — releases slot, checks out the ongoing ticket (or synthesizes a finished ticket), returns `{slot, ticket}`.
- **Zones**: 6 seeded (A North $10, B South $12, C EV $15, D West $11, E East $13, F Valet $18, 45 slots); CRUD at `/api/zones`; creating/editing a zone **auto-syncs slots** (creates/removes `prefix+N`).
- **Sessions**: `GET /parking/sessions` (entry/exit history), `GET /parking/peak-hours` (24-int hourly occupancy array).
- Frontend map: stat cards, zone overview grid, slot grid with legend + zone pager, search by slot/plate, per-slot dialog (park/reserve/check-in/release/maintenance), **checkout modal** with card (VISA/MC/Amex auto-detect) and **cash-with-change** flows.
- **Analytics sub-view**: zone utilization, peak-hour bars, avg stay/turnover/peak-occupancy.
- **Vehicles sub-view**: table of currently parked vehicles.

## 4. Reservations (`/api/reservations`)
Full lifecycle: `POST` (create, validates slot available, sets slot reserved) → `PUT /{id}/checkin` (→ACTIVE, writes plate/owner) → `PUT /{id}/complete` (→COMPLETED, clears slot) → `PUT /{id}/cancel` (→CANCELLED, releases slot). Statuses: `RESERVED/ACTIVE/COMPLETED/CANCELLED`. Stores reservedFor/type(member|staff)/email, plate, vehicleType. Frontend `ReservationHistory` component shows history with zone/type/status filters. Seeded: 25 reservations.

---

## 5. Tickets & Billing (`/api/tickets`)
- `ParkingTicket`: vehiclePlate, ownerName, slot, entry/exit, amount, status (ONGOING/FINISHED), vehicleType (CAR/SUV/MOTORCYCLE/TRUCK/VAN), paymentMethod, ratePerHour.
- **Pricing**: `amount = ceil(hours, min 1h) × ratePerHour`; default rates by type (10/15/5/20/12).
- **Filters**: status, vehicleType, paymentMethod, slot, date range, amount range.
- **Checkout**: `POST /tickets/{id}/checkout?paymentMethod=`.
- Frontend `TicketsView`: 4 stat cards (collected & pending revenue), search/sort, filter tabs with counts, detail modal, checkout modal (card/cash), **overdue flag (>240 min)**.

---

## 6. Members Management (`/api/members`)
- CRUD + `suspend/activate/deactivate`; stats (`total/active/inactive/suspended/professional/basic/totalVehicles`).
- `MemberModal`: +94 Sri-Lankan phone, username (lowercase/no-spaces), password strength meter, **plan selector with monthly/annual billing (−20% badge)**, **vehicle editor** (add/remove plate/type/make/color rows), status dropdown, card payment preview strip.
- Table: search, status tabs, plan filter, avatar/plan/vehicles/status, hover actions (QR view + **PNG download**, edit, status toggle, remove).
- Plans (`/api/plans`): CRUD, `calculate-savings` endpoint, seeded Basic ($9.99/$99.99), Professional ($19.99/$199.99, popular), Premium ($29.99/$299.99) with features/maxVehicles.

---

## 7. Staff Management (`/api/staff`)
- CRUD incl. **multipart avatar upload** (saved to `data/uploads/`); JSON + FormData variants.
- Access-level editor with `customPermissions` checklists; `accesslevel.txt` sync side-effect.
- Seeded 15 staff across all access levels. Frontend: stat cards, search + access filter, avatar, DOB/gender, vehicle section (plate/type/make/color), activate/deactivate.

---

## 8. Reports (`/api/reports`)
- Types: Occupancy, Revenue, Member Activity, Tickets, Vehicle Log, Zone Summary.
- Generate (`POST /reports/generate`), list, stats, fix/unfix (resolution workflow), **download** (blob, filename from Content-Disposition).
- `ReportSummary` (dashboard): occupancy, peak-hours, weekly traffic, revenue estimates (ticket = sessions×10, membership = members×50 — simulated).
- Frontend `ReportsView`: dashboard (stats + live activity feed), add report, view (search/filters/fix/delete/download).

---

## 9. Settings (`/api/settings`)
- **General**: facilityName, timezone (28 options), currency (9 options), darkMode, autoRefresh (30s polling).
- **Security**: sessionTimeout, failed-attempt lockout (maxFailedAttempts, lockoutDuration, limitEnabled).
- **Zone defaults** (`/settings/zones`): default slots, rates, vehicle types, overflow/auto-release.
- **Access control** (`/settings/access-control`): role permissions, MFA, session/lockout defaults.
- **History** (`/settings/history`): paged ticket history with filters (date, zone, plate, status, member), sorted by entry time.
- Profile settings & password security (frontend).

## 10. Dashboard & Analytics
`AnalyticsSection`: 4 gradient stat cards (Total Revenue, Occupancy, Active Members, Zones), revenue breakdown, member-status donut, sessions overview, **weekly traffic AreaChart**, **vertical ComposedChart** zone occupancy, plan pricing BarChart. 30s auto-refresh + manual refresh. Dashboard hidden from members.

---

## 11. AI Assistant ("Parker" chat widget)
- Floating chat widget with suggestions, typing indicator, unread badge.
- `POST /api/chat` (JWT-authenticated) → **Groq** OpenAI-compatible endpoint (`llama-3.3-70b-versatile`) via `AIServiceImpl`.
- **Member-scoped vs staff-scoped context**: builds prompts with slots/zones/revenue/tickets/members/staff/open reports; **declines member questions about non-member data**. Friendly fallback when `AI_API_KEY` not configured.

---

## 12. Payment Validation (no real gateway)
`POST /api/payments/validate-card`: bean validation + 10-year expiry window + **Luhn algorithm**; `POST /api/payments/check-username`. Used by member registration. Billing is display/logic only — no real processing or expiry enforcement.

---

## 13. Seed Data (`MockDataSeeder`, deterministic `Random(42)`)
3 plans, 6 zones (45 slots), **30 members** (1–3 vehicles each, mixed statuses), **15 staff**, slot states (18 occupied/5 reserved/2 maintenance), **~150 sessions**, **~60 tickets** (45 finished/15 ongoing), **25 reservations**. **Idempotent**: if plans exist, only runs `repairSlotStates()` (re-randomizes only if <5 occupied AND 0 reserved) and `repairMemberVehicles()` (backfills vehicles for legacy members).

---

## 14. Architecture Notes & Known Gaps
- **Three-layer repo pattern**: `XxxRepository` interface + `@Primary Sql*` (JPA/H2) + `File*`/`InMemory` (dev profile) implementations.
- QR generation, DTO mappers, file storage with per-file read/write locks.
- **No scheduling/async**; **no tests** under `src/test`.
- Frontend duplicates local types across files (sync warnings); backend URL hardcoded in `api.ts` and `reportService.ts`; 61 shadcn `ui/` components exist but are unused by feature views (inline Tailwind used instead).
